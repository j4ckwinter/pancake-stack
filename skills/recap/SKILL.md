# Recover the working context

Read [core values](../pancake/references/values.md) and applicable repository instructions. Return a grounded brief of the requested work. Recap does not authorize continuing implementation, changing files, or contacting others.

Start with the current conversation, supplied notes, and relevant handoffs. Use a complete supplied state summary rather than searching history again. Establish the project and topic from the request and workspace. For requested recent history with no date range, state a seven-day window; honor an explicit range or request for all history without silently narrowing it.

Search previous conversations only when the user requests historical recovery and the available context is insufficient. Use a host capability that can identify sessions by their recorded workspace metadata. Do not infer project ownership from filenames, scan all user transcripts, or assume another host's transcript layout or record format applies to the active host. Filter to the requested project, time range, and topic before reading relevant records. Exclude the current conversation and synthetic or delegated runs when identifiable. Interpret records according to their actual format, and preserve source references that can be inspected. If scoped history access is unavailable, say so and summarize the evidence available; do not install a history tool or read unrelated chats.

Reconcile relevant prior statements with current artifacts. In a repository, inspect the branch, HEAD, status, and the relevant diff or history using read-only commands. Read only files that clarify the recovered work. Distinguish prior reports from fresh observations and identify later decisions that supersede earlier plans. A clean tree does not prove publication, and an old passing check does not verify a changed artifact.

Use supplied tickets, PRs, and other records when they resolve a consequential gap. Access external sources only within the requested scope and available permissions; do not sweep every service by default. Label inaccessible sources and unresolved contradictions rather than filling them with guesses.

Lead with where the work stands. Include the objective, accepted decisions and known reasons, completed and unfinished threads, relevant verification and gaps, and the next useful action. Keep proposed, local, committed, and confirmed delivered work distinct. Cite inspected artifacts or identifiable supplied records beside the claims they support. Omit credentials and unrelated personal details. Keep the brief proportional rather than reproducing a transcript or imposing fixed status labels.

Return the brief in chat. Save a file only when requested. If the user asks to resume work as well, use [handoff continuation guidance](../handoff/references/continuation.md) to reconcile state before acting within that authorization.
