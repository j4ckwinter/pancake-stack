# Capture personal working preferences

Use when the user asks to capture or revise their working style. Reflecting on a task does not automatically authorize creating a personal profile. Keep individual preferences separate from shared Pancake instructions and setup's model and reasoning-effort configuration.

Start with explicit preferences and corrections in the current conversation and supplied notes. Honor a clear preference without requiring repeated evidence. Treat inferred habits as proposals, supported by recurring examples rather than one incidental task choice. Preserve later corrections and label contradictions or context-dependent preferences. Do not convert task-specific authorization into a standing permission to commit, publish, message others, or change global settings.

If the user requests historical analysis and current context is insufficient, use [Recap](../../recap/SKILL.md) to establish project, topic, date range, and safely scoped source access. Do not mine unrelated chats, inspect every personal skill, or assume transcript locations. Lack of history is an evidence gap, not a reason to invent a preference.

Identify the requested scope and destination before saving. A project instruction affects collaborators; a personal skill affects its invocations. Explain that distinction when choosing placement. Locate an existing profile only within the named or established scope, preserve unrelated conventions, and propose the smallest update. Return a draft in chat when saving or the destination is not authorized. Do not write into the installed plugin cache or silently modify global instructions.

Capture concrete choices that change agent behavior, such as response depth, review expectations, or a named workflow. Keep each instruction scoped to the situation where it applies. Omit generic advice, duplicate skill contents, and inferred personality traits. Reference relevant skills only through paths or identifiers available in the target environment; disclose missing dependencies instead of creating broken-looking links.

For a requested personal skill, use [active host guidance](../../pancake/references/host-runtime.md) and the host's skill-authoring guidance and the user's chosen location and invocation policy. Do not assume a personal mode applies on every turn or force an invocation restriction the user did not request. Model preferences belong in the existing setup mechanism rather than a competing profile schema. Personal conventions remain subject to current user instructions and host permissions.

Review the draft against the evidence. Distinguish explicit choices, inferred proposals, and unresolved conflicts. Validate a saved skill's structure and references; that does not prove the profile matches the user's intent. Report what was saved and where, or return the draft for feedback. Do not automatically install, commit, publish, or test the user's preferences through unrelated agent tasks.
