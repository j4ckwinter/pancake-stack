# Sift the prose

Make the text useful on the first read. Apply these choices while drafting, then check the result for lost meaning. Match the audience, requested tone, and document purpose. Preserve deliberate voice rather than making every text sound alike.

## Keep the substance

Preserve facts, uncertainty, caveats, commitments, and actions. Keep exact identifiers, commands, links, measurements, and quotations intact. Do not invent evidence to make a sentence more concrete. A stylistic edit must not turn an estimate into a result, a plan into completed work, or a reported check into a fresh observation.

Name what happens, who acts, and why the reader needs to know. Replace vague praise or benefit claims with an existing concrete fact. If no supporting fact is available, remove the unsupported claim or retain the uncertainty. Use one name consistently for each concept.

## Remove the friction

- Lead with the answer or requested action. Remove automatic acknowledgements, flattery, previews, and generic closing offers.
- Cut repeated points and padding such as "it is important to note". Prefer "use" to "utilize" and "help" to "facilitate" when the meaning is the same.
- Replace ornamental jargon and metaphors with the actual mechanism. Keep precise technical terms when they help the intended reader.
- Split sentences that carry competing thoughts. Keep complete sentences and necessary articles instead of compressing prose into fragments or arrows.
- Prefer active voice when the actor matters. Keep passive voice when naming the actor would be speculative or distracting.
- Remove stacked hedges while preserving real doubt. "May" can replace "could potentially", but uncertainty established by evidence must remain.
- Use formatting to aid reading. Avoid decorative emphasis, repeated inline labels, forced groups of three, and headings that merely repeat the next sentence.
- Prefer periods to long dashes and unnecessary mid-sentence colons. Preserve punctuation in literal text and follow explicit user or repository style requirements.

Do not treat a word list as a ban. A word is a problem when it adds no meaning or obscures the point. Brevity must not remove the explanation a reader needs.

## Technical documentation

When drafting or editing technical documentation, read [technical-writing guidance](references/technical-writing.md) to choose the reader's purpose and check instructions, terminology, and factual claims. Ordinary conversational prose uses the guidance above directly.

## Return the work

For an explicit rewrite, use the supplied passage or clearly identified file. If neither is available, ask what to edit. Return the revised text without a report about the cleanup unless requested. Edit files only when file editing is authorized, preserving unrelated content. Do not investigate the repository or use external sources merely to restyle supplied prose.

When used inside pancake, apply this guidance to progress updates, explanations, authorized documentation and comments, continuation notes, and final replies. It changes the writing, not the requested workflow or permissions. Do not announce a cleanup pass or rewrite existing files simply because the skill was loaded.
